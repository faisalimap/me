Git wrapper / Windows

Two identities.
One working tree.

Kit is a lightweight CLI wrapper around Git for using a second GitHub identity without creating a second repository, switching installations, or changing how your project is structured.

01 / Why KitSame Git. Different route.

The idea

Keep Git familiar.
Make identity switchable.

01

Same repository

Git and Kit operate on the same working directory and the same .git repository. Your commits, branches, staging area and history stay ordinary Git.

02

Second config

Kit maintains a parallel configuration for its second identity, then supplies that configuration when a Kit command needs it.

03

Two destinations

Normal Git can continue using one remote and identity while Kit uses the second setup, letting the same local history reach both accounts.

02 / How it works

Nothing replaces Git.
Kit sits beside it.

Kit is intentionally a wrapper, not a new version-control system. Commands are forwarded to Git, while Kit-specific configuration is supplied for the second identity.

The local project remains a normal Git repository. Remove Kit and the repository is still a Git repository.

# normal Git
git push

# Kit, using its parallel config
kit push
→ forwards to git.exe with Kit's configuration

# configuration remains per project

03 / CommandsFamiliar syntax by design.

Workflow

Use Kit where
you need another identity.

01kit status

Inspect the same working tree Git sees.

02kit add .

Stage changes in the same Git index.

03kit commit -m "update"

Create a normal Git commit using Kit's configured identity.

04kit push

Push through Kit's configured account and remote.

05git push

Continue using ordinary Git for the other account.
